# EXT-2026-11-10 — external leads for DeepSeek-V4.1-Flash decode throughput on 4x RTX PRO 6000

Read-only digest of 4 assigned sources + the trail they opened. Constraint honored throughout:
single-stream decode speed on 4x RTX PRO 6000 (SM120, 96GB, PCIe, no NVLink), **without changing
model weights or output quality**. Ideas are tagged `exact` (bit-identical output), `gate`
(numerics change; needs a quality gate), or `weights` (re-quantizes; excluded by the constraint).
All fetches done 2026-11-10 via GitHub API / raw.githubusercontent.com / arxiv.org.

## Source 1 — https://github.com/MiaAI-Lab/GLM-5.3-Flash-2x-RTX-PRO-6000-TensorFold

**What it is.** Deployment recipe + 100+ engine patches (shell, MIT) for running GLM-5.3-Flash
(61.7B MoE) EXL3 4bpw on 2x RTX PRO 6000 (TP2, one host) under **TensorFold** — a native Zig/CUDA
inference server, upstream `github.com/ashhart/TensorFold` @ f350cd3e, compiled with Zig 0.17.0 for
sm_120 (README :26). Created 2026-10-31, 23 stars, pushed 2026-11-07.
**Hardware/model:** 2x RTX PRO 6000 Blackwell 96GB (sm_120), CUDA 13, NCCL P2P_LEVEL=SYS (no
NVLink); GLM-5.3-Flash 1017 EXL3 4bpw (164GB) + optional DFlash2 drafter.

**Benchmarks (their own, exact quotes):**
- README :40-41: `Total tok/s | 245.5 | 336.6 | 385.5 | 436.6` / per-stream `245.5 | 169.1 | 132.0
  | 110.3` at 1/2/3/4 streams — "RTX PRO 6000 production host at 400 W, prose decoding (temperature
  0.7, thinking on)". Prefill "~5,500-6,000 tok/s" with graphed chunks.
- CHANGELOG :24 (2026-11-07, greedy, PARALLEL=4, DENSE=q8 HEAD=q8): "decode 171-172 tok/s at one
  stream and 294-296 summed at four"; with KV_SHARD=1: "176 -> ~170 tok/s at one stream (-3.5%),
  KV pool +8%, full 1,048,576-token window fits".

**Architecture facts that matter for transfer (README :200-206):** "34 KDA layers at 64 heads x
128, 11 full-attn MLA layers, first_k_dense_replace 3, 288 routed experts top-8, moe_intermediate
2048, vocab 154,880" — i.e. GLM shares MLA + MoE + MTP + DSA with DSV4.1, but 3/4 of layers are
GLM-specific KDA.

**Transferable mechanisms** (patch files verified via
`https://api.github.com/repos/MiaAI-Lab/GLM-5.3-Flash-2x-RTX-PRO-6000-TensorFold/contents/patches/engine`,
filenames `NNNN-glm-cuda-*.patch`):
- 0001: "EXL3 mcg experts at any whole bit width, mixed by projection" — mixed 3/4-bit experts by
  projection; **weights — excluded by constraint**, but the mechanism (per-projection width table,
  mixed layers routed to the grouped decode path) is the reference impl for bit-mixed experts.
- 0005-0006, 0017-0025: E4M3/FP8 latent-attention KV + shared 512-row KV page pool (KV=fp8,
  KV_PAGES=on). README :157, :276-277.
- 0013-0014, 0036, 0040: DFlash2 speculative drafting (separate drafter model, 16-way argmax
  candidates, adaptive window by expected tokens/ms). README :144-147.
- 0026-0033: sm_120 load-ahead grouped-expert kernels (upstream #1505/#1534). README :319-321.
- 0034-0035: one-shot P2P all-gather for decode + copy-engine prompt exchange. README :319, :158.
- 0041: ABSORB_MMA. 0064: W8A8 prompt linears (parked). 0067-0068: DSA select many-CTA + in-kernel
  merge. 0069-0090: PDL chain. 0103: LEARN_GIB conversation resume. 0104: KV_SHARD (README :167:
  "about 1.8x the tokens in the same memory", costs ~3.5% single-stream decode).
- README :150 PREFILL_SHARE=0.68; :215-216: "With PREFILL_SHARE=1 ... drops to about 4-5 tok/s, with
  a pause of about 420 ms before every token".

**docs/deepseek.md** (misleadingly named; = "GLM-5.3-Flash on 2x RTX PRO 6000: where decode and
prefill time actually goes", 298 lines, kernel-level analysis with file:line citations):
- Baseline: prose decode ~170 tok/s / 7.59 ms/step; code ~277; file-edit ~514 (greedy). Ranked
  levers: D1 occupancy (+15-30% decode), D2 split-K without global partials (7.08 -> 5.4 ms window,
  +8-12%), D3 deeper load-ahead, D4 expert shard 46/54 by clock (rank-0 desktop GPU is ~16% of
  step), D5 drafter headroom. Prefill: P1 rows-per-block traffic arithmetic, P2 chunk rows,
  P3 W8A8+ABSORB (10-19%), P4 overlap, P5 rotate fold, P6 attention chunk body to MMA (SIMT fp32
  today). Roadmap target :20: "245.5 tok/s ... to 370 tok/s and the step from 7.59 to 5.0 ms".
  All estimates, not measurements — treat as a work plan, not results.

**Would NOT transfer to DSV4.1-Flash:** KDA-layer kernels (DSV4.1 has no KDA); DFlash2 drafter
(GLM-only + CC BY-NC-ND); EXL3 mixed-width (EXL3 container, and re-quant = weights); GLM-TP3/twin-
rank pairing (2-host topology trick); 512-row page layout sized to GLM's 3,542 B/token latent row.

## Source 3 — https://arxiv.org/abs/2010.03494 (TeaForN)

**What it is.** Paper: "TeaForN: Teacher-Forcing with N-grams", Sebastian Goodman, Nan Ding, Radu
Soricut (Google Research), v1 2020-10-07, v2 2020-10-09. PDF read: /tmp/teaforn.pdf via
https://arxiv.org/pdf/2010.03494.

**Method:** training-time only. "a stack of N identical decoders and ... a secondary time axis
running n steps in the future" — trains the model to look N steps ahead under teacher forcing;
addresses exposure bias and differentiability. Results: WMT14 En-Fr +0.3 BLEU, CNN/DailyMail +0.2
ROUGE; GPT-2 117M NLL -0.08; "PEGASUS large trained with TeaForN matches the prior ROUGE-L scores
... without beam search, representing an 8x reduction in decoder inference cost."

**Verdict for this project: NOT TRANSFERABLE.** (1) It requires retraining the model — violates
"without changing model weights". (2) The 8x claim is beam-search elimination in NMT/summarization
serving; chat decode (greedy/sampled) never paid that beam cost, so there is no single-stream tok/s
delta to harvest. (3) It is a quality method, not a serving-speed method; the arXiv abstract itself
frames it as exposure-bias/differentiability work. No decode-throughput numbers exist in the paper.
Relevance is nominal only — the *name* resembles n-gram speculative decoding (e.g. DSpark/
DFlash2-style drafting), but the mechanism shares nothing with inference-time speculation.

## Cross-cutting notes for the 4x PRO 6000 build

1. The single highest-confidence, lowest-effort lever is speculative decoding with the checkpoint's
   own draft blocks (DSpark, k~7; vLLM-Moet already demonstrates 2.2-2.7x on this model+hardware).
   The GLM data (RESULTS.md :417) warns: A/B the built-in MTP head against the full drafter at your
   batch sizes — MTP was a wash at 1 stream and negative under load there.
2. Measure the verify cost line on PRO 6000 before tuning draft length (Repo2's 38.73 + 5.68*(rows-
   1) ms is GB10-only). Per-row expert traffic scales with rows because each draft row selects its
   own top-k experts.
3. Quality gate tooling transfers as-is from Repo2: fixed-prompt decode benches, interleaved ABA
   (host drift ~1.5%), contract hash equality for `exact` ideas, NLL for `gate` ideas.
4. DSV4.1-Flash-specific machinery to exploit that GLM-5.3 lacks: mHC sublayers (overlap +3-5%),
   ratio-1 indexer layers (paged MQA logits), 384 experts at TP4/EP2, FP4 KV record.
